# PostgreSQL 数据参考

用于数据模型、SQL、索引、约束和迁移任务。先检查 PostgreSQL 主版本、Schema 组织、ORM/SQL 层、迁移工具和已发布的数据库契约。

## 建模与约束

- 遵循现有命名、主键、审计字段、软删除、版本列和 Schema 约定；不要自行引入新的全局模板。
- 让数据约束表达稳定的不变量：根据语义考虑 `NOT NULL`、`UNIQUE`、`CHECK`、外键以及默认值。若约束有意放在应用层，说明一致性边界。
- 选择与数据语义相符的类型、精度、时区和空值策略。评估 JSON/JSONB 是否保留了确有价值的灵活性，避免把有稳定关系的字段无理由藏入文档列。
- 索引应服务真实查询、连接、排序或唯一性需求。索引会增加写入和存储成本；检查谓词、列顺序、选择性和现有索引后再添加。
- PostgreSQL 的具体功能、DDL 选项和锁行为会受服务器版本影响；版本敏感的决定先查目标版本文档。

## 迁移与运行风险

- 使用项目既定迁移工具和版本策略，不以手工改库替代迁移记录，也不擅自重写已在其他环境运行的迁移。
- 评估旧应用与新 Schema 的兼容窗口。高风险变更可拆成扩展、回填、切换、收缩等阶段。
- 对大表重写、长事务、索引构建、默认值回填和锁定风险，估算数据规模与执行时间；需要时选择并发/分批方案并核对该版本的限制。
- 数据回填应可重入、有边界并可观察。删除列、收紧约束或不可逆转换前，确认旧数据处理、备份和恢复方案。
- 不在未获授权的情况下对非隔离数据库执行迁移、导入、清理或破坏性 SQL。

## 查询与事务

- 只选择必要字段，使用参数绑定；动态表名、列名和排序语法需由允许列表构造。
- 检查分页排序是否稳定、过滤是否可走索引、事务是否过长，以及并发写入下是否存在竞态或重复执行。
- 依据项目现有隔离级别和冲突处理方式处理并发；遇到死锁/序列化失败时，确认可安全重试的边界。

## 文档同步

若新增/删除实体、修改字段、迁移或约束，按项目规则同步数据模型、迁移说明和 API 类型文档。数据库列名、表名前缀和字段顺序都以目标项目为准。
