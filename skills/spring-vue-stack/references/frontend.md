# Vue 3 前端参考

用于 Vue 3 页面、组件、Composable、路由、状态及服务端 API 集成。首先检查目标项目的 Vue/TypeScript 版本、构建工具、UI 库、状态库、路由、请求层和 lint 配置。

## 组件与状态

- 沿用项目已有的 Vue/TypeScript 版本、SFC 语法、组件组织、命名规则和模板风格。新增代码默认让 Vue 组件/页面目录采用 PascalCase，API、Store、Composable 文件采用 kebab-case；若仓库已有一致规则，遵循仓库规则。
- SFC 块顺序遵循项目 lint/格式化配置；没有既有配置时统一采用 `<script>`、`<template>`、`<style>` 顺序。不要为调整块顺序而无关改写整个组件。
- 组件围绕清晰的 UI 职责组织；可复用的状态行为适合放入 Composable，跨页面共享状态应使用项目已有的状态方案。
- Props、Emits、`v-model`、服务端结果和关键状态使用明确类型声明；在 `<script setup>` 中遵循项目 Vue 版本支持的 `defineProps`、`defineEmits`、`withDefaults` 和 `defineModel` 写法。不要使用 `any` 掩盖不兼容；在外部数据边界进行类型窄化或运行时解析。
- 根据状态来源选择本地、路由、服务端缓存或全局状态。不要把可从当前视图推导的数据重复保存为另一份状态。
- 呈现加载、空结果、成功、失败和禁用状态；交互组件应保留键盘操作、标签和可感知的错误提示。

## API 与异步行为

- 业务请求统一经过项目已有的 API 模块和请求客户端；不要在业务组件中直接调用 `fetch`/Axios，也不要为单个页面另加一套请求封装。上传/下载同样使用项目已有的文件传输封装。
- 对接前核对服务端路径、参数、权限、分页、错误包装、二进制响应和认证机制。API 类型应反映实际契约。
- API 请求/响应类型的字段名应匹配线上契约；本 Skill 约定的 JSON 字段使用 `snake_case`。若前端业务模型使用 camelCase，在 API 边界通过明确的类型或转换函数处理，不要静默假设请求客户端会自动改名。
- 区分网络失败、业务失败、取消和过期响应。对快速切换筛选或路由造成的并发请求，遵循项目的取消、去重和竞态处理方式。
- 对缓存、重试和持久化逐项确认数据是否用户相关、权限相关或安全敏感；避免陈旧或跨用户数据泄露。
- 前端权限控制用于界面体验，服务端仍必须执行最终授权。
- API、Store、Composable、共享类型及路由配置放在项目既有目录并遵循已有命名/导出约定；不要为局部功能增加平行请求层、状态容器或路由注册体系。

## 路由和表单

- 遵循项目的静态/动态路由、守卫、权限元数据、页面布局和导航生成方式。
- 表单校验与服务端约束保持一致；服务端返回字段错误时映射到对应输入，同时保留可理解的全局错误。
- 对提交、删除、发布和批量操作提供清楚的进行中与结果反馈；不可逆或有较大影响的操作采用项目既有的确认方式。

## 验证

发现并使用项目已配置的格式化、lint、类型检查、组件测试和构建脚本。测试沿用项目的测试运行器、Vue Test Utils/组件库和 Store mock 模式；不要为单个修改擅自引入另一套测试框架。开发时优先运行目标测试或类型检查，交付前按项目约定执行完整门禁。

修改 API 接口或字段时，检查后端契约、API 模块、共享类型和所有受影响页面；修改路由或权限元数据时检查守卫、菜单/导航生成和授权配置；修改上传/下载时检查服务端约束、请求封装及文件响应处理。检查 package scripts 是否已通过 `prestart`、`prebuild` 等生命周期钩子执行相关检查，避免重复串联同一命令；不要虚构项目不存在的命令。
